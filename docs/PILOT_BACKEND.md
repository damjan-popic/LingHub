# Private pilot backend

`pilot_app:app_factory` serves only the invited pilot surface. It is separate from the existing LingHub application, source indexes, model endpoints and operational database. Run it in the dedicated `pilot` environment with `--factory --no-access-log --no-proxy-headers`. It listens on loopback; the configured protected edge is responsible for HTTPS and forwarding the authenticated application only.

## Configuration and credentials

`KLIKAI_PILOT_CONFIG` names a private JSON file. Required fields are `store` (a new private absolute SQLite filename), `allowed_origins` (exact origins), `gateway_url` (explicit loopback URL), and `gateway_token_file` (0600). `secure_cookies` defaults true; HTTP cookies are permitted only for explicitly configured loopback development. `base_path` is empty or a normalized prefix such as `/pilot`. `models` defaults to `qwen,gemma`; `tasks` defaults to `reference,source_search`. Add `text_check` only with a configured `linghub_url`; it uses `/v1/analyze` with the existing default analyzer and preserves deterministic checks. The development prose presets `jezikovna_urgenca` and `jezikovna_posta` each require explicit inclusion in `tasks` and a configured `klikai_url`; they do not alter the existing ZRC `source_search` route.

Production uses `allowed_origins: ["https://klikai.jeziknaklik.it"]`, secure cookies and a protected `edge_token_file`. The edge must remove client-supplied identity headers and set `X-Pilot-Edge-Token` and `X-Pilot-Client-IP` from its observed client. The latter is parsed as an IP address only after the secret boundary token matches. Forwarded headers and participant IDs from the browser are never trusted. Raw generator, retrieval, database, gateway, management and diagnostic endpoints are not mounted by this app.

Argon2id uses 64MiB, three iterations, one lane and at most two simultaneous password operations. Passwords accept 12–1024 Unicode characters. Initial/reset passwords expire after 24 hours and require replacement. Opaque server-side sessions have a 30-minute idle limit and eight-hour absolute limit; cookies are HttpOnly, SameSite=Strict and Secure in production. Login, password changes, resets and role changes rotate or revoke sessions. Account and actual-client throttles use salted HMAC identifiers, not stored raw IP addresses. Tester, reviewer and administrator permissions are enforced separately; reviewers see only explicitly assigned review records. The last enabled administrator cannot be removed by simultaneous administrative mutations.

## Browser contract

All paths below are prefixed with `{base_path}/api/pilot`. Authenticated writes require JSON, an exact allowed `Origin`, and `X-CSRF-Token` from `GET /session`. Login requires JSON and the origin but has no pre-login CSRF cookie. Optional `X-Pilot-Locale: sl|it` selects localized failures. Error responses have `{error:{code,message,locale}}` and never echo request bodies or provider exceptions.

| Route | Result or payload |
| --- | --- |
| `GET /session` | `{authenticated,csrf_token,user,capabilities}` |
| `POST /login` | `{username,password}` |
| `POST /password`, `/logout` | `{current_password,new_password}`, `{}` |
| `GET/POST /families` | History `{families:[...]}`; create `{question,context?,locale,interface_locale?,model,task,idempotency_key}` returns `{family,job}` |
| `GET /families/{id}` | Immutable family, short and long tiers |
| `POST /families/{id}/expand` | `{idempotency_key}` reuses the saved bundle and parent; no new retrieval |
| `GET /jobs/{id}`, `POST /jobs/{id}/cancel` | Owned persistent state; job contains `job_id,state,family_id,tier,position,error_code` |
| `POST /runs/{id}/delivered` | `{display_sha256,expanded}` after actual rendering |
| `GET /families/{id}/sources/{evidence_id}?tier=short` | Owned source drawer; exact evidence membership checked first |
| `POST /comparisons` | `{family_id,blind:true,tier:"short",idempotency_key}` |
| `GET /comparisons/{id}` | Persisted A/B mapping; `short`, `long`, current `sides`, vote and prior exposure flag |
| `POST /comparisons/{id}/expand` | Same A/B assignment, both long jobs and one frozen evidence packet |
| `POST /comparisons/{id}/delivered` | `{tier,expanded}`; server records both real display hashes |
| `POST /comparisons/{id}/vote` | `{choice,tier,idempotency_key}`; choices A, B, equivalent, both_inadequate, cannot_judge |
| `POST /comparisons/{id}/reveal` | Requires a saved vote |
| `GET /comparisons/{id}/sources/{evidence_id}?side=A&tier=short` | Assignment-owned source drawer |
| `GET/POST /feedback` | Own current feedback; revisioned submission described below |
| `POST /account/export`, `/account/delete` | `{current_password}`; deletion has durable replay tombstones |
| `GET /admin/accounts`, `POST /admin/accounts` | Invite `{username,role,temporary_password,reauth_password}` |
| `POST /admin/accounts/{id}/reset`, `/disable`, `/role`, `/delete` | Reauthentication plus the requested scoped field; revoke sessions |
| `GET /admin/overview`, `/admin/feedback` | Counts/cycles; administrator or assigned reviewer records |
| `POST /admin/feedback/{id}/assign`, `/triage` | Administrator assignment; scoped reviewer triage |
| `POST /admin/pause`, `/revert`, `/export` | Pause `{paused}`; sensitive revert/export require `reauth_password` |

Tier `state` is queued/running/complete/failed/cancelled. Completed canonical results preserve `short_answer`, `answer_md`, `source_badges`, `evidence`, support/kind and limitations. `blocks` contain exact display text and stable block IDs; named tiers also carry the display hash. Pending tiers carry the existing job ID. Unrevealed blind pairs hold both results until both sides are terminal; pending side run/job IDs and per-side progress are withheld, and known job polling is masked. Private bundle signatures, policy/profile/model pins, timings and raw provider errors are never sent in blind responses; opaque random run/job IDs do not encode the model. Named/revealed sides identify their model. Assignment mapping, finished result bytes, family identities and feedback/vote revisions have database immutability guards.

Feedback accepts `run_id`, optional `rating` (useful/partly_useful/not_useful), `tags`, `comment`, `proposed_correction`, `idempotency_key`, optional `feedback_id` and `target:{kind:"answer"|"source",evidence_id?}`. Null usefulness ratings are allowed for selected-error reports. Optional `anchor:{block_id,start,end,quote,prefix,suffix}` uses Unicode code-point, half-open offsets; exact quote and surrounding text must match the displayed stored block. Client offsets are not guessed or repaired. Every revision is appended. A retry with the same key/payload replays its acknowledgement; changed payload with a reused key returns409.

The queue admits at most30 active jobs globally and four per account, with at most two generator workers, one active generator job per account and one per selected model, plus one separate worker for source search and deterministic text checks. Short requests have priority; jobs waiting60 seconds precede new short requests. Cancellation is persistent; a late completed provider response is discarded after cancellation. A single-process lock prevents concurrent worker instances. Interrupted running jobs fail explicitly on recovery and are not automatically inferred again. Queued jobs retain their IDs across restart.

## Analysis, bounded adaptation and recovery

Use `python -m pilot_backend --store /private/pilot.sqlite COMMAND`:

- `init` initializes only this store. Existing unrelated SQLite databases are refused without modifying their permissions.
- `invite-admin --username NAME --password-file /private/600-file --bootstrap-id RUN_ID` atomically records the account and activation marker. Exact replay returns the original account without resetting its password; mismatched identities refuse. `bootstrap-status --bootstrap-id RUN_ID` is read-only and reports only readiness, account ID and forced-change state. Omit the ID for one-time manual bootstrap that refuses an existing administrator.
- `analysis --output-dir /private/analysis` writes deterministic counts, triage IDs, bounded suggestions, and Slovenian/Italian summaries. Its input cutoffs and run identities make replay deterministic; missing report files are repaired from the original stored report. Human/synthetic/imported/test counts are separate and feedback revisions are deduplicated. Raw comments are never treated as model instructions. No background generator invocation is needed to produce valid counts.
- `adaptation --config /private/backend.json --cases /private/exposed-cases.json --cases-sha256 SHA [--candidates /private/600-candidates.json] [--validation /private/600-validation.json]` uses at most three deterministic allowlisted suggestions when explicit candidates are absent. It needs20 new human reference events, three participants and ten cases; targeted language slices need ten cases and three participants. Otherwise it records `INSUFFICIENT_DATA` and `ANALYSIS_ONLY_NO_VALIDATED_PROMOTION`. Insufficient/rejected attempts do not consume feedback; newly supplied validation can be considered at the same cutoff.
- Validation may be supplied in the owned0600 mapping file or per-policy file `validation-inbox/{candidate_policy_id}.json` beside the store. This is trusted operator-reviewed evidence, not a browser endpoint or a model's self-assertion. It must pin baseline/candidate IDs and `source_model_profile_cohort_pin` from the analysis snapshot, identify an independent human/source reviewer, assert completed development/regression/deterministic checks, and supply at least30 source-reviewed held-out pairs. Each pair identifies source group, case, source-review SHA256 and measured scores/latencies; groups cannot overlap the development evidence. Minimum gain is0.02, critical regressions zero and reference p95 ratio at most1.1. This is an engineering gate, not proof of general linguistic superiority. Missing or failing independent evidence never promotes.
- Only implemented context limits, fixed short/long style presets and rerank policy can change. Lexical-weight changes remain rejected until the private gateway implements and tests a real weighted-fusion control. No source authority, answer text, source data, code, arbitrary prompts, permissions, model revisions or analyzer defaults can be changed by this promoter.
- `monitor-canary --config /private/backend.json` observes the bounded candidate; every completed public job also checks immediate failures. Ten percent of eligible new reference families receive a stable account-based candidate allocation. Source search and deterministic tools stay on the active baseline. Existing families/comparison packets retain their saved policy. Twenty eligible human reference runs must finish inside48 hours; CPU work cannot influence the reference baseline or count. Critical/excess technical failures and family/runtime identity drift revert immediately; insufficient traffic keeps the baseline. Promotion needs a fresh private identity observation, and administrator pause is checked again in the final transaction. Health probes occur outside database write transactions. Job callbacks without a live identity client cannot promote. `revert` returns to the parent configuration atomically. No GPU, service or system command is available to the promoter.
- `backup --archive /private/NEW.tar.gz` uses SQLite's committed online backup, then includes the monotone deletion ledger. The tar and its members are0600. `restore --archive ARCHIVE --destination NEW_PRIVATE_DIR --current-deletions CURRENT_LEDGER --sha256 SHA` verifies members, restores only a new disposable leaf, replays later deletion/retention entries, revokes sessions, marks interrupted jobs and checks SQLite integrity/foreign keys. It never overwrites the live account store.
- `verify-backup --archive ARCHIVE` verifies the exact three regular members, schema, lengths, SHA256 hashes and deletion chain in place, without extraction or mutation. A scheduler can reconcile a completed archive whose receipt was interrupted. Corrupt partial leaves stay available for inspection; another attempt uses a new filename. The disposable SQLite snapshot removes session rows with secure deletion and vacuuming; the live sessions are unchanged.
- `recovery-support --feedback-archive ARCHIVE --current-ledger LEDGER --signing-key KEY --backend-config CONFIG --gateway-config CONFIG --pins-file PINS --archive NEW_SUPPORT.tar.gz` creates a bounded private seven-member support package. It includes the verified account backup, current deletion ledger, protected evidence signing key, explicit configurations and sanitized fixed code/source/vector/model policy pins. It excludes bootstrap passwords, session material, gateway/edge token contents, model weights and raw source files. Credential-bearing metadata and raw body fields are refused. Configuration token-file paths may remain as restoration instructions; replacement authentication tokens must be provisioned separately.
- `restore-support --archive SUPPORT --destination NEW_PRIVATE_DIR --sha256 SHA` checks the inventory and every member hash, restores only into a new private directory, then performs the separate account-store restore with the current deletion ledger. It proves key and data recovery without starting services or changing pointers. A synthetic signed-bundle test verifies the restored key using the gateway's exact canonical HMAC format. Reopening real frozen families also requires the matching fixed code/policy and source/vector/model releases; the support archive does not embed those large assets. Keep this archive encrypted for any separately authorized off-host copy.
- `retention` applies the fixed180-day pilot setting, separately from read-only analysis. It appends/fsyncs a retention tombstone before deleting expired raw feedback/votes/deliveries and inactive answer families. Restoring an older backup replays this cutoff so expired records cannot reappear. Keep the current ledger with the protected backup plan. This is an operational retention choice, not a legal claim.
- `recovery-exercise --directory NEW_PRIVATE_DIR` runs an actual synthetic two-account/feedback/blind-vote backup, deletes one account after the backup, restores separately and proves preserved records, watermarks, deletion replay and interrupted-work handling.

The root deployment owns the actual nightly02:15 and Monday03:15 Europe/Ljubljana persistent timers, plus scheduled backup/retention. CLI implementation or local receipts do not imply installed timers or off-host durability. Local proof reports `offhost_verified:false`; encrypted off-host copying is a separate deployment responsibility and requires a real configured destination.

## Validation

`/data/envs/lingstack/pilot/bin/python -B -m pytest -q tests/test_pilot_backend*.py` uses private disposable stores and a clearly synthetic adapter. It covers authenticated ownership, CSRF/origin/host boundaries, Unicode anchors, random blind mapping and reveal order, persistence/idempotency/cancellation, password rotation and throttling, atomic bootstrap/schema, policy gates, independent source-group separation, canary promotion/rollback/no traffic, actual archive restoration and deletion/retention replay. Live browser/model tests and deployment evidence are recorded separately; no participant data belongs in Git or the code review pack.

The optional `terminology` task requires `klikai_url` pointing to the accepted loopback KLIKai API. It uses `/api/terminology/lookup` with no partial/prose search, admits only whole-query exact or zero-ambiguity morphology-exact forms, and freezes the complete returned records and response digest. Source access uses that stored copy under the existing ownership check; it never repeats the live lookup. No model, expansion or model comparison is invoked. An explicit no-hit invites a separate question. Source/domain records are kept separate.

## Luka prose search presets: development contract

The five terminology collections are Šolska (`solska`), Zvezek (`zvezek`), CrossTerm (`crossterm`), ZKB (`zkb`) and Tretji sektor (`tretji_sektor`). Jezikovna urgenca (`jezikovna_urgenca`) and Jezikovna pošta (`jezikovna_posta`) are two separate prose/Q&A collections. They are reached through their configured choices in the existing task selector and normal `POST /families` flow, with the selected preset as `task`. No acceptance-only endpoint or hard-coded query is required.

Each prose preset sends the entered query to accepted KLIKai's `GET /api/search` with `q=<query>`, `sources=<that one preset slug>` and fixed `limit=3`. Admission remains confined to the selected source. The deterministic result presents attributed search excerpts as potentially relevant published advice, not a synthesized answer to a different question. Records, document identities and source references remain separate. Text uses the normal escaped rendering path; source material cannot issue application, tool or model instructions. A no-hit or upstream failure does not substitute another source or invoke generation.

The admitted search response and its identity are frozen in the normal owned capture. The owner's source drawer reopens that saved material without another upstream search; other users cannot retrieve the capture, drawer or family by guessing its identifiers. No model generation, expansion or comparison is used. Existing terminology, ZRC routes and historical captures are unchanged by this additive development path.

This is an excerpt contract, **not a complete Q&A reader**. The accepted search API does not provide the full original question/answer association, source date or a detail route from which to retrieve those missing fields. In particular, a Pošta result title is not its original question. Do not relabel titles as questions, infer missing dates, combine records into an answer, or present a bounded snippet as the full editorial explanation. Available labels, document identities, titles, rights and links are retained as supplied; missing optional provenance stays missing. Completing faithful full-Q&A presentation remains blocked on the accepted upstream contract.

The earlier five-source terminology matrix passed against live accepted lookup and isolated pilot state. On 2026-09-14, 60 targeted backend tests and 17 UI helper tests passed; both live prose excerpt cases passed with two searches total, and the unchanged five-source live terminology matrix passed once. Evidence: `/data/scratch/damjan/klikai-human-testing-20260911/linghub/luka-prose-implementation-acceptance-20260914.json`. This verifies isolated API/answer-block/drawer behavior and UI helper logic, not a browser session. Complete Q&A acceptance remains blocked by the upstream contract. The deployed pilot, its configured tasks and accepted KLIKai remain unchanged. Retained-release identity, accepted-code identity and captured-response identity are separate: **live database edition is unverified by the current lookup contract**. No browser or deployed-pilot acceptance is claimed here.

New `text_check` families require explicit `input_language=sl|it`; `locale` controls the explanation labels independently. The UI preserves the selected text language when switching SL/IT chrome. Historical families retain their original frozen analyzer choices and outputs.

## Periodic replay and comment triage

`replay --config /private/backend.json --cases /private/exposed-cases.json --cases-sha256 SHA [--max-cases 1..4]` runs baseline plus one implemented candidate against at most four previously exposed development/regression cases. The manifest freezes questions, locale, tier, model, source choices/groups and original case hashes. Reserved groups and embedded gold/source-body fields are refused. The scheduler performs this bounded smoke replay before adaptation. With fewer than20 eligible human reference events, three participants or ten families, it returns `INSUFFICIENT_DATA` with zero gateway/model calls. Administrator pause is respected. Explicit `--force-test` permits a technical exercise whose artifacts can never support promotion or create human labels. Four cases are not the full120-case evaluation or semantic certification.

Replay uses a private single-instance lock, durable request hashes/cursor and immutable response artifacts. It checks the public queue before every request and defers while work is queued or running; a bounded request already in flight can finish. Completed responses are reused, including a response saved just before a receipt interruption. An interrupted request without a response is never silently repeated. The CLI lowers its own scheduling priority.

Independent validation must additionally name the completed `replay_run_id`. Its reviewed source groups must be separate from replay groups. The machine gate verifies every artifact, the currently configured case manifest, source/vector/base-generation/model/profile pins, and active embedding/reranker contracts. It rejects stale, incomplete, changed and test-only receipts. Identity is observed before and after each paired case and before promotion. Technical success never substitutes for independent human/source review.

Analysis extracts bounded neutral phrase themes from comments/corrections and links each summary to exact feedback/event/revision IDs. Unclassified wording remains explicitly for a reviewer. These are unverified participant mentions, not instructions, correctness labels or arbitrary prompts. Raw comments are not copied into long-lived reports, so their180-day retention remains meaningful.

Replay cursor, request hashes, case summaries and runtime pins are mirrored into SQLite cycle records. Selected independent-review metadata, its input digest and measured pair scores are retained with adaptation decisions. The ordinary protected account backup therefore preserves the explanation of a promoted policy. Raw replay response bulk is intentionally outside the compact support archive. After restoration, missing response artifacts block reuse and new promotion; completed/interrupted requests are not regenerated under their old identity. A later period may create a fresh replay from the verified exposed manifest. Recovery does not claim to preserve every historical model response.
