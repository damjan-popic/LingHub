# Internal human-testing pilot

Enable `human_testing_mode: true` and `comparisons_enabled: false` in the existing backend configuration. The mode is also retained in the account store, so scheduled tools defer automatic adaptation, canary progression and replay even if model capacity and old eligibility thresholds are satisfied. Analysis and protected backups continue. Existing assignments, answers, votes, feedback revisions and accounts remain available.

Each displayed short or expanded answer has one initially unselected 1–5 quality scale, an optional comment and one submit button. Selecting a score alone never submits it. Saved scores reappear on reload; unsaved edits are identified. The existing detailed issue annotation remains a secondary action. All controls and administrator viewing are available in Slovene and Italian.

The additive `family_inputs` table preserves newly submitted questions exactly, including Unicode and surrounding whitespace. Existing normalized questions are retained and are explicitly marked as lacking an exact original capture. The additive `feedback_observations` table binds each new immutable feedback revision to its server-derived participant, origin, original question, displayed paragraphs and readable answer text, display hash/version, selected and actual model, actual CPU/GPU backend, language, tier, policy, source revisions, vector snapshot and UI asset hashes. Paragraphs retain exact text and are joined with two newlines in readable exports; the displayed expanded-answer correction notice is included. Existing event rows and the older usefulness scale are never rewritten or mapped to numeric scores.

Authenticated administrators can view these records and export JSON or CSV from the feedback tab. JSON preserves literal strings. CSV prefixes formula-leading strings with an apostrophe for spreadsheet safety; the JSON export is the exact-text format. Neither export includes passwords, sessions, credentials or signed evidence packets. Owners' exports exclude other participants and the global analysis. Source text and comments render as text, not HTML.

Nightly analysis reports `counts.human_quality` (1–5 histogram, mean and number rated) using only `origin=human` answer feedback. Synthetic, imported and test activity have separate origin groups. No test account is promoted to human eligibility by these changes.

The UI accepts the gateway's model-specific CPU availability, preserves the chosen model, and keeps normal queue polling responsive. The generate request alone permits up to 3600 seconds for bounded CPU loading, queueing and inference; ordinary browser API requests retain their short timeout. Actual completed result model/backend identity is displayed. Website startup does not load a model or depend on a GPU. CPU resource allocation, model selection and system-service deployment remain with the existing controller and gateway.

Focused validation: `tests/test_pilot_human_feedback.py`, selected existing auth/feedback/backup checks, and `tests/test_pilot_ui_human_feedback.cjs`. The browser fixture is explicitly synthetic; live CPU generation, network access and controlled persistent-service restart evidence are separate integration checks.
